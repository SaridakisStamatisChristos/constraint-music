# Paired cross-system conformance v1

This bounded second study is complete: 48 held-out attempt slots, 432 fault slots and 36 planned PPQN controls are archived and replayed. [REPORT.md](REPORT.md) and [summary.json](summary.json) are generated from the bytes. It follows the earlier native/adapted pilots without changing them, and does not pool their counts or PR37's counts.

The primary delivered endpoint passes 12/12 Constraint Music, 11/12 music21, and 12/12 adapted Diatony requests. Diatony's native identity/context remains UNOBSERVABLE. All 36 primary attempts returned outputs; 12 additional attempts are explicitly UNSUPPORTED. Of 432 faults, 420 apply: 385 REJECT, 35 BLOCKED, zero PASS; 12 are INAPPLICABLE. All eight hand controls and 35 applicable PPQN controls pass. One PPQN slot is inapplicable. These observations do not establish arbitrary-input reliability.

## Inspect and replay the archived evidence

Outside execution requires the owner's written permission under the unchanged [license](../../LICENSE). See the [permission route/template](../../docs/RESEARCH_REPLAY_PERMISSION_TEMPLATE.md). Public source visibility is not an automatic execution grant.

After obtaining permission, from the repository root:

```bash
python -m pip install -e . mido==1.3.3
git fetch --no-tags research/history/paired_cross_system_v1.bundle \
  refs/heads/research/paired-cross-system-benchmark-v1:refs/assurance/paired-cross-system-v1-original
python -m research.paired_cross_system_v1.runner check
python -m research.paired_cross_system_v1.analysis --check
```

This replay reconstructs stored native scores and invokes both semantic implementations and both MIDI parsers. It checks original Git protocol objects, collection/fault hashes, unique/complete attempt and fault sets, trusted requests, native-input binding, native-score equality, mutation bytes, verdicts, exact member coverage and deterministic summary/report derivation. It requires no CP-SAT/music21/Gecode generator execution and no network after dependencies/history are available. It is an independent implementation replay here, not a completed replication by an outside team.

`development/evidence.zip` and `heldout/evidence.zip` contain actual files under `attempts/<request-id>.<system>/`. Each row's `files` map records exact members and SHA-256. Native input/score/MIDI and delivered MIDI remain separate. `heldout/fault_bytes.zip` contains deduplicated actual mutated artifact and MIDI bytes; `faults.jsonl` links every slot to its baseline and bytes. Do not interpret identical content hashes as independent samples.

To inspect without running repository code:

```bash
python -m zipfile -l research/paired_cross_system_v1/heldout/evidence.zip
python -m json.tool research/paired_cross_system_v1/summary.json
```

ZIP members can be read directly; evidence is neither fetched nor regenerated by the checker. `DEVELOPMENT.md` and `development_v0.zip` preserve the earlier pre-freeze native-rule differences, original code and outputs. Active declaration commit `167ed84` precedes freeze receipt `ff15f25`; the collection index binds that receipt to its collection commit. This is local prospective history, not external preregistration.

## Generate a new study version

Do not overwrite or rerun the frozen version. Copy the study into a new version, select fresh request identities/families, declare any changes before results, and retain the old archive. Generation needs the versions in `manifest.json`, a clean checkout of [Diatony](https://github.com/sprockeelsd/Diatony) at `2b13446c117c02626659e819ff975fef4b5daec2`, Gecode 6.2.0 and a C++11 compiler. External licenses/notices remain upstream; no source or binary is vendored here.

The build helper accepts a Gecode installation prefix with `usr/include` and `usr/lib/x86_64-linux-gnu`. Debian-compatible extracted development/runtime packages satisfy that layout; on another layout adjust only a newly declared build version.

```bash
python -m pip install -e '.[dev]' mido==1.3.3
python -m research.paired_cross_system_v1.build \
  /path/to/clean/diatony /path/to/probe /path/to/gecode-prefix
```

The workflow for a newly declared version is development collection, development validation/commit, freeze, freeze-receipt commit, held-out collection, attacks, analysis and archive checking. Its runner refuses existing archives. Do not delete an old archive to bypass this protection. Recompilation can change binary hashes across toolchains; the original binary hash pins the local collection, while archived-byte replay remains portable. The binary is deliberately not redistributed.

## Natural counterexample

`heldout.extended-submediant.Eb.music21` passes request/native-score binding and exact MIDI delivery, but its third block (time 8 quarters) has pitch classes {8,10,2}; the requested IV triad in Eb requires {8,0,3}. The native bass is spelled G-sharp in the archived MusicXML because the adapter constructs bass notes from integer MIDI pitches. This is consistent with an enharmonic translation issue in the adapter/native realization path; it is not evidence of a general music21 defect. No held-out-informed spelling repair was made. A future adapter version must declare an explicit diatonic spelling policy and use a fresh holdout.
