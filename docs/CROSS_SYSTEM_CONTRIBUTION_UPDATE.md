## Evidence-supported contribution

The implemented contribution is a versioned, prospective cross-engine conformance protocol with explicit request admission, native-score reconstruction, two separate semantic implementations, two delivered-MIDI parsers, and complete planned-slot/eligible-fault accounting. Its bounded result is 35/36 accepted primary delivered endpoints, one retained semantic discrepancy, and zero accepted applicable injected faults. Diatony's 12 adapted endpoints do not count as native endpoints; native identity/context is unobservable in all twelve. All raw inputs, scores, actual files, failures, controls and hashes are retained.

The music21 discrepancy arises in the Eb extended family under integer-MIDI bass construction: the native bass spelling is G-sharp, and the resulting block differs from the requested IV triad. An enharmonic adapter translation explanation is consistent with the evidence; causal confirmation requires a separately declared experiment. This is not a general library defect claim.

The paired difference between Constraint Music and music21 is one request out of twelve. Four two-family cluster resamples give an illustrative difference range of 0 to 1/6, not a confidence interval. There is no population-random sample, independent mutation sampling, aesthetic evaluation, speed comparison on identical native search models, or global novelty proof. The candidate paper contribution is the concrete combined protocol/evidence boundary, not an unsupported priority claim for its individual ingredients.
